# lib/engine/app/input

## Responsibility
The `engine.app:input` module defines the input abstraction layer for the PPR game engine. It provides the type definitions and interfaces for keyboard, mouse, and gamepad devices, along with the action/mapping system, modifier/trigger events, exponentially filtered analog shaping, and the `InputContext` listener-routing tree that higher-level systems (player service, UI, gameplay) use to consume input in a device-agnostic way.

Recent refactor: the per-device `device/` subdirectory (`Gamepad`/`Keyboard`/`Mouse` partitions) was removed and consolidated into the unified `engine.app:input.device` partition; the standalone `App.Input.Mapping` partition was removed and merged into `engine.app:input.action`; `App.Input.Replay` was removed entirely; `App.Input.FilteredAnalog` and `App.Input.Device.cpp` were added.

## Design
- **InputValue** variant type (`digital`, `axis_1d`, `axis_2d`, `axis_3d`) carries per-key state with absolute/relative values; `modulate(float/float2/float3)` uses `std::visit` + `overloaded`: digital gates the constant (`input ? value : 0`), same-rank axes scale componentwise, cross-rank composes (`1D+1D→2D`, `1D+1D+1D→3D`, `2D×float2`, `3D.xz` projection, `float3(x,0).xzy` lift); `modulate(dt, v)` scales by `time::seconds(dt)`; `hashValue`/`opaqueValue` visit the payload; `relocatable<InputValue>` is `true_type`
- **InputKey** wraps `InputKeyCode` (variant of `EAnyKey`/keyboard/gamepad/mouse enums) plus `InputValueType` to classify the value kind; equality/ordering/hash key on `m_code` only; `isKeyboard/isGamepad/isMouse` visit the code; `from(device-enum)` maps to canonical static aliases (unmapped `stick2/3`, `trigger2/4` → `nullopt`, otherwise `unreachable`); `enumerateAll` combines the five per-device enumerators; static aliases (`any_digital`, `any_axis_1d/2d/3d`, `mouse_2d`, wheel axes, gamepad sticks/triggers, full keyboard set) are the only bindable identities
- **InputAction** holds a description, value type, flags (`consume_input`, `trigger_when_paused`), optional `ModifierEvent`, and per-transition `TriggerEvent` callbacks (`setStarted`/`setTriggered`/`setCompleted`); static `modulate()` factories include a generic `GetValueT` overload projecting sampled state into the action value
- **InputActionKeyMapping** (key → action binding with optional per-binding modifier/trigger callbacks) and **InputMapping** (`StableVectorInplace` keymap with `mapInputKey`/`unmapInputKey`/`unmapInputAction`/`clearInputMappings`) now live in `engine.app:input.action` (moved from the deleted `:input.mapping` partition); `mapInputKey` dedupes by `(action, key)` identity and returns the existing entry; `unmapInputKey` erases by pointer identity
- **InputModifierEvent** (`TimeSpan dt, InputValue &value`) — modulates an action's value before triggering
- **InputTriggerEvent** (`event, trigger`) — fires on action started/triggered/completed transitions; `EInputTriggerEvent` (`inactive → started → triggered → completed`); `InputActionEvent` carries source action, optional value, elapsed trigger time, and repeat count, with `getIf*`/`get*` typed accessors (`std::get`/`std::get_if` over the value variant)
- **IInputDevice** (`safe_object` base) — `getInputDeviceID()`, `enumerateSupportedInputKeys()`, `pollInputMessages(dt)`, `resetInputState()`; `InputMessage` carries key, value, device id, and event (`pressed`/`released`/`repeat`/`double_click`/`axis`) with `is*`/`get*` accessors
- **InputAxisState<T>** template — `m_next_raw_absolute` staging, dead-zone gate (`dot2(relative) > dot2(dead_zone)`), exponential filter blend `saturate(pow(elapsed, 1/max(sensitivity, eps)))` via `lerp`; `set`/`add`/`addClamp` feed raw input, `update(elapsed_seconds)` advances raw + filtered, `postInputMessages(dt, context, device_id, key, enable_filtered)` posts raw or filtered after asserting `input_value.getType() == key.m_value` (extern instantiations for `float`, `float2`)
- **InputDigitalState<ButtonT>** template (constrained to enum/integral) — `FlatSet` pressed-set: pressed posts `pressed`/`repeat` (inserted or not), erase posts `released`, unknown key logs verbose and returns false (extern instantiations for `EKeyboardKey`, `EGamepadButton`, `EMouseButton`)
- **KeyboardDevice** (digital keys + `m_character_inputs` text buffer cleared at the top of `pollInputMessages` before window events, forwarded via `postCharacterInput`), **MouseDevice** (button set, cursor-pos `float2` axis via `set`/`update`/`post`, per-axis wheel `float` accumulators via `add`/`update`/`post`, opt-in `m_has_axis_filtering`), **GamepadDevice** (button set, stick `float2` axes, trigger/rumble `float` axes, per-group filtering flags, `isConnected()` via `m_controller_id != none_v`) — all consolidated in `engine.app:input.device` (moved from the deleted `device/` per-device files)
- **FilteredAnalog<T>** (`engine.app:input.filtered_analog`) — exponentially filtered analog accumulator (`m_raw`/`m_delta`/`m_filtered` + `sensitivity`); `add`/`addClamp`/`setRaw` feed raw input, `update(dt)` advances the filter; `Quaternion` gets explicit specialization treatment; extern templates for `float`, `float2`, `float3`, `Quaternion`
- **InputListener** — defaults to `consumed` mode; `PrioritySet` of mappings, `FlatMap<action, InputActionEvent>` live action state, `FlatMultiMap<key, InputBinding>` rebuilt keybindings; `setActionCallback`/`setCharacterInputCallback`/`setRawKeyCallback`; `EInputMessageResponse` listener mode (`unhandled`/`handled`/`consumed`); `postKeyEvent` short-circuits on `unhandled` mode, runs the raw-key hook first (non-`unhandled` returns immediately), drops `isAny` keys, then dispatches `equal_range` bindings with action-then-binding modifier application and trigger state transitions
- **InputContext** — priority-ordered listener set with optional parent chain (`getParentContext`); `addInputListener`/`removeInputListener`/`postKeyEvent`/`postCharacterInput`; posting walks listeners by priority: `consumed` returns immediately, `handled` accumulates, then the parent chain runs the same way; move-only (const `m_parent`, out-of-line move ctor)
- **WindowInputContext** — binds an `IInputService` + `Window`, parents its context to the service global context, registers via `addInputContext`, and subscribes the five window delegates (character/keyboard/mouse-clicked/moved/scrolled) into `IInputService::post*` calls; dtor resets all delegates and calls `removeInputContext`; mouse-moved forwards GLFW client-space positions as-is
- `IInputService` interface (defined in `engine.app:service.input`) provides the device-agnostic posting contract; all types reside in `namespace pP` and use `safe_ptr`, `string_literal`, `Numeric<T>`

## Flow
1. Device front-ends (`GlfwInput` hot state, `WindowInputContext` window callbacks) call `post*` entry points carrying the target `InputContext`
2. Digital state (`InputDigitalState::postInputMessages`) emits pressed/repeat/released messages; analog state (`InputAxisState::postInputMessages`) emits axis messages in raw or filtered form after dead-zone/sensitivity shaping
3. `InputContext::postKeyEvent` walks listeners by priority (then parent chain) with consumed-short-circuit/handled-accumulate semantics; each `InputListener::postKeyEvent` runs the raw-key hook, resolves keybindings via `equal_range`, applies action-then-binding modifiers, and drives trigger state transitions (`pressed → started` with fallthrough into `triggered`; `repeat`/`double_click`/`axis → triggered` with repeat counting; `released → completed` with count reset)
4. `rebuildKeybindings_` preserves live `InputActionEvent`s across rebuilds, drops later bindings once a `consume_input` mapping claims the key, and expands `AnyKey` bindings via `enumerateAll` filtered by value type
5. Per-frame, `pollInputMessages`/`pollInputDevices(dt)` flush accumulated axis/digital state (keyboard clears the char buffer first); `resetInputState` clears transient state (focus loss, device reset)

## Integration
- **Consumers**: `GlfwInput` (hot devices + global/per-device contexts), `GlfwPlayer`/`PlayerGraph` (per-player listeners), `ImGuiService`, `Application` (per-frame poll), camera controllers (`provideInputActionKeyMappings` + `setTriggered/setStarted/setCompleted` callbacks)
- **Depends on**: `engine.core` (Numeric, safe_ptr/safe_object, FlatSet/FlatMap/FlatMultiMap/PrioritySet, TimeSpan, Collector, overloaded, opaque), `engine.math` (float2/float3/Quaternion vector types), `engine.app:service.input` (posting contract), `engine.app:window.handle` (Window delegates), `std`
- **Provides**: `engine.app:input.action`, `engine.app:input.device`, `engine.app:input.filtered_analog`, `engine.app:input.key`, `engine.app:input.listener` module namespaces (no `:input.mapping`, `:input.replay`, or `device/` sub-partitions remain)
- **Used by**: `IInputService` (service.locator), `Application.update()` → per-frame device poll, `ImGuiService` for ImGui integration
