## Goal and acceptance

Make the interactive `app.game` understandable and usable with a mouse and keyboard: move quickly across a 4096×4096-cell colony at any zoom, locate and follow its three colonists, see what is under the pointer, dig and place existing rock-wall orders using discoverable controls, pause/step/change speed, and diagnose performance without a CLI. The fixed-plane XY camera is **not** a free-look camera. Correct mouse handling means intentional grab-pan, pointer-anchored wheel zoom, reliable world clicks and UI exclusion; do not add yaw/pitch to disguise the broken Pan bindings.

The first usable milestone is slices **0–4** below: navigation, reliable input/picking, visible controls, and finding a colonist. Build placement and performance polish follow. A slice is done only when its observable acceptance cases pass in an actual interactive window as well as in tests. Headless `--smoke` alone cannot establish playability. The user-approved contact-history behavior and prior colony simulation gates remain intact.

## Interaction contract to establish before tool expansion

1. **Route, do not erase.** Binding rebuild retains lower-priority candidate bindings independently of current consume state. The listener/context's existing dispatch-time response determines propagation. Keep existing priorities and public action/mapping API; do not replace the input framework, introduce generic contexts/chords/replay, or change Free/Orbit behavior. A previously suppressed non-consuming callback may now run: explicitly test this migration risk.
2. **One gesture owner.** Press decides whether the world tool, UI, or camera owns a pointer gesture. Ownership persists through its release even when the pointer crosses a panel. An accepted command has separate lifetime from a held gesture: cancellation can stop future work but cannot erase an already accepted click. Consume the final owned release **before** relinquishing ownership. Do not route a world press that started over UI to the world when the cursor leaves UI.
3. **Input source of truth.** Establish client-space pointer coordinates from window/device messages and a current, unjittered camera snapshot, not last frame's UI/game cursor cache. Pixel/DPI coordinates must agree with the viewport. Recompute hover after camera update even if the pointer is stationary; clear it outside the client rect, on invalid ray/plane intersection, or when UI owns the pointer. Do not bypass ImGui capture just to sample coordinates.
4. **Cancel/reset.** On focus loss, device disconnect/reset, viewport loss, tool change, regeneration, or an appropriate UI capture transition, clear transient camera rates/buttons and tool gestures; define separately whether a previously accepted command completes. Probe editor wiring before adding shared reset machinery. Holding movement then opening UI must not leave a stuck pan.
5. **Simulation boundary.** Button and shortcut produce the same typed game-owned intent; UI widgets only return intents/view requests. Apply writes through existing explicit `ColonyDriver` methods at a defined update boundary. Preserve deterministic command ordering for a given input sequence; never make the sim consume wall-clock/UI state. Selection, follow, hover and debug overlays are view-only and not snapshotted.

## Slice 1 — narrow input hardening (critical path)

**Engine binding sub-slice:** in `App.Input.Listener.cpp`, retain all compatible candidate bindings during rebuild; keep priority order and response semantics at dispatch. Preserve live action state on rebuild. Tests in `lib/engine/tests/app/App.Input.Listener.Tests.cpp` (check actual filename) must cover consuming→transparent without rebuilding, reverse transition, same-key priority order, and mapping remove/re-add. Audit AnyKey and duplicate-key behavior before changing the loop.

**Game gesture sub-slice:** replace interdependent `m_pending_pick`/`m_dig_mode`/held flags with a small game-owned gesture state and queued accepted tool command(s). The press snapshots owner/tool and client position; release completes exactly once. Continuous dig should request each distinct traversed valid cell at most once per intended visit (define dedup/brush behavior explicitly); a quick press/release must still dig once. Tool switching/Esc cancels current drag without committing a build order. A world-origin drag moving across UI stays world-owned until release, subject to explicit cancel policy; a UI-origin drag never acquires world ownership. UI widgets do not directly mutate simulation.

**Gate:** synthetic same-poll press/release, repeat, double-click, world→UI/UI→world, held-key capture, focus loss, device reset, regeneration and tool switch; owned release must not leak to selection/camera; first world click after UI interaction must use its current coordinates. Run affected Input.Listener/WindowInput/ImGuiRouting tests and interactive clicks. If input routing cannot provide reliable current coordinates, stop and resolve that seam rather than patching gameplay with a stale pointer.

## Slice 2 — playable fixed-plane camera (parallel, then integrate)

- Restrict movement changes to Pan controller and game camera setup. Keep `Camera` snapshot/matrix convention (`view * projection`, row-vector, LH +Z) and Free/Orbit unchanged. Orthographic scale `s` is world-units/client-pixel; target keyboard pan ≈ **600 client pixels/s** at nominal speed, so world-speed law is `v_world = s * 600` units/s (with explicit speed modifier and finite/clamped `dt`). Tune with user-visible testing rather than inheriting a 3-units/s free-flight constant. Bounds must account for visible half-extents at each zoom, keep the colony on-screen, and gracefully center when the viewport is wider than the world.
- Use **MMB held grab-pan**, not unguarded mouse-2D motion. For a cursor delta `Δp`, translate camera by the negative world-space projection of that delta at current scale (grabbed ground stays under the cursor); calculate signs from the actual camera basis and viewport, not screen-Y intuition. RMB must not silently enable a non-existent Pan rotation path. Preserve gamepad movement only if its speed law is well-defined; offer keyboard WASD/arrows.
- Wheel zoom changes finite, clamped ortho scale exponentially, anchored at the cursor's ground-plane intersection: world-before and world-after at the same client position agree within tolerance unless a world bound forces a clamp. Wheel over UI belongs to UI. Resize/DPI change and invalid viewport are explicit no-op/error cases, never NaN.
- Add a game-owned **Focus** camera target (teleport/cut or smooth with bounded convergence) and optional Follow hook for Slice 4; manual pan/zoom cancels Follow or follows a documented policy. Do not let profiling-only `--profile-pan` flags redefine normal input behavior.
- **Gate:** tests for equal screen displacement across zoom extremes and `dt` partitions, exact drag direction, no cursor-only pan, zoom anchor invariance, clamp/finite properties, and Free/Orbit regression; interactive traversal from colony center toward edges in seconds, MMB drag with UI overlay, stationary cursor after zoom, DPI/resize/minimize/restore and focus-loss release. The visual feel gate belongs to an actual person using the window.

## Slice 3 — readable controls, picking, dig and main window

### UI layout (designer-owned implementation)

An always-visible top **simulation bar**: `[Pause/Resume] [Step] [1× 2× 3×] | [Inspect] [Dig] [Build ▾] | [Seed] [New world] | [Performance] [?]`. A second contextual **tool strip** names the active tool, mouse gesture, brush/rectangle size and Cancel/Esc. The central world remains mouse-pass-through. A docked/right panel has `Colony` and `Performance` tabs plus a persistent `Inspector` section; bottom status line shows hovered cell/element, selected target, useful instruction or validation error. At narrow widths, wrap/overflow controls rather than hiding Dig. Use font-relative sizing, keyboard-navigation-compatible ImGui widgets, readable contrast and text alongside color; test 100%, 150%, 200% DPI.

- **One intent vocabulary:** `PauseToggle`, `Step`, `SetSpeed(1/2/3)`, `Regenerate`, `SelectTool(Inspect/Dig/BuildWall/Demolish)`, `ToggleEditHighlight`, `Cancel`, `FocusSelection`, `TogglePerformance`, `Help`. Shortcuts and buttons dispatch the same intent path. Keep Space/N/1–3/R/G/H; add I/Esc/F1/F3 only after checking actual conflicts; B opens a menu, never places a wall by itself. Show shortcut next to each action in tooltips/Help (avoid a second hardcoded, drifting map).
- **Tool semantics:** default Inspect (or visibly selected neutral pointer); Dig has a visible 1-cell world hover outline and status reason for invalid/vacuum/nonresident targets. A quick LMB click digs one valid cell; a held drag digs intentionally and stops on release. UI clicks, wheel and panel drags never dig. Tool selection is explicit and highlighted. A newly generated world resets hover, selection, tool gesture, translator presentation and follow safely.
- **Picking:** consolidate `pickCell_` into a tested current-cursor world hit (orthographic fixed plane). Derive integer cell only after finite bounds checks; expose invalid/nonresident reason. Use unjittered camera snapshot and client coordinates, clear stale hover after pan/zoom/UI capture. Preview and action must use the same resolved target; no separate UI-only guess.
- **Error behavior:** invalid user placement or a recoverable dig/build failure is visible in the tool strip/status (short-lived, dismissible; retains an error code), not a silent default or an unconditional process exit. Initialization/render/shutdown failures continue to propagate. Add only a bounded game-owned notice state, not `Player::pushFrameMessage` (cleared each frame). Regen gets a confirmation for destructive replacement (or a clearly labeled seed/reset affordance), so users do not lose the visible colony by accident.
- **Gate:** toolbar-click and shortcut parity, paused Step enabled only while paused, speed state, seed/regeneration, click/drag over world and over every panel, accurate hover after keyboard pan, UI keyboard focus not leaving movement stuck, no input to simulation on hover/inspect. `--smoke` remains unchanged; an interactive scripted/manual checklist is mandatory.

## Slice 4 — locate, select, focus and follow colonists

- Make colonists discoverable before adding more build options: readable world marker/outline at default zoom, selectable `Colonists` rows (`A0…`, state, O₂/rest, goal, plan/replans), and a clear **Focus** button on each row. A list click pins selection; Focus moves camera to its current world position at a useful bounded zoom and visibly highlights it. Follow is opt-in with an obvious Stop-follow control; manual navigation cancels it. Do not move agent entities by focusing.
- CPU hit-test at the world pointer using the **same submitted pose/scale** as the visual quads, with a minimum screen-space pick radius and explicit nearest/tie policy; prioritize colonist over wall cell when overlapping. Clicking a wall cell inspects element, temperature and coordinates. Clicking an **active build order** may inspect its footprint/progress only if Slice 0 confirms a stable errand identity; a completed rock wall is a cell, not a persistent building. Avoid using a panel row index as identity: validate a stable entity key/generation each frame and clear selection on deletion/regeneration.
- Inspector shows `Hovering` vs `Pinned`, coordinates/element/temperature, colonist status and plan with honest empty/unknown states. If agent position differs between physics/render/summary, use the rendered pose for hit tests and mark the displayed source; do not invent exactness. Optional one-click “Find next colonist” for tiny/offscreen agents uses stable ordering.
- **Gate:** click agent from list and world at several zooms, overlap tie, focus centers within viewport tolerance, follow tracks across ticks and cancels on manual pan, selection invalidation after regen/entity removal, no sim hash/clock/snapshot changes from inspect/focus, keyboard navigation and high-DPI hit targets. If stable identity is unavailable, deliver list focus via a verified stable key first; do not ship fragile row-index selection.

## Slice 5 — real build menu and placement

- Popup/menu exposes only **Rock wall** and **Demolish** using existing `ColonyDriver::buildWall(Footprint)` and `demolish(min,w,h)`/`BuildErrand` pipeline. No doors, rooms, machines or ladder placement unless separate verified simulation/render support lands; do not label a solid wall as a door. Replace the vague “buildings” promise with wall orders plus inspectable completed wall cells.
- Press on valid world cell sets an anchor; drag previews inclusive rectangle, capped at existing `kMaxFootprintEdge` (currently 32; verify constant), visibly states clamping/invalid reason; release commits **one** order. Esc, focus loss, tool change, UI-origin press or rejected placement commits none. Use driver validation for terrain and error codes rather than UI-only validation. Explicit paused behavior: orders may queue while paused but execute only after Step/Resume; show `Queued` until progressed.
- Reuse the one typed intent path for keyboard and button. Success feedback should state rectangle size and order state; failure does not consume or mutate cells. Render preview in existing game-owned debug submission, not `Renderer` content logic.
- **Gate:** rectangle corners and world edges; 1×1/32×32/>32 clamp, UI capture, fast press/release, cancel, paused queue/progress, regeneration while gesture active; compare resulting cells/dirty chunks/errand count against equivalent direct driver commands. Re-run dig/build/snapshot/determinism smoke and simulation/app tests; no snapshot format change for view state.

## Slice 6 — performance tab and scoped quality-of-life

- Add a `Performance` tab with clearly distinct **Frame**, **Simulation**, **Presentation**, **Work queue** sections. Frame samples must state the exact boundary: `dt` is inter-frame elapsed time, a timed `update()` is update CPU time, and neither is GPU or end-to-end present duration. If showing frame percentiles as full frame/present pacing, instrument the actual boundary first; otherwise label them `Inter-frame delta` or `Update CPU`. Keep a bounded recent window (e.g. 240 samples), explicit p50/p95/max and >16.67 ms count, sample count and reset/window definition. Refresh display at a bounded cadence while sampling each frame.
- Driver and translator `StageTimings` are separate accumulated tables with calls/mean/max/total in µs. Four counter-only rows (cache hit/miss, needed cells, drained chunks) are **counts**, never µs. Show collider pending, last edit/dirty and grid/tile cache/upload counts with cumulative vs instantaneous labels. `simMs()` belongs under `Simulated time`, not performance cost. No fabricated GPU ms; explain that no GPU timestamp query is present. Do not reset existing profiling accumulators invisibly or change CLI CSV output.
- Add `Help` with camera/tool shortcuts and a brief first-run hint or reopenable onboarding panel. A lightweight agent list + Find action and a grid/edited-chunk overlay toggle are high-value. Status/notice text reports why a click did nothing. Defer minimap, full key rebind, persistence, custom font assets, multi-cell dig brush, ladders/doors and deeper entity inspection until the core loop is usable and measured. Layout persistence is optional; if implemented, use an established writable user-data location and propagate/report recoverable filesystem errors per repo contract, not silent install-directory writes.
- **Gate:** table labels agree with measurement scopes and paused/reset behavior, percentile math/window-size unit tests, bounded memory/refresh overhead, active backlog and no-backlog display, tab usability during 100-agent `--profile100`, DPI/keyboard navigation. Re-run `--time-trials` and `--profile-csv` compatibility; they are diagnostics, not substitutes for interactive evidence.

**Final walk-through:** from a fresh launch at ordinary 1280×720 and 150% DPI, find a colonist from the list, focus/follow then manually pan to cancel, zoom under a stationary pointer, use MMB grab-pan across several chunks, inspect a ground cell, dig via both G and toolbar with one click and a drag, place a small wall order and see it progress while stepping, undo by demolishing, regenerate after confirmation, then read real counters during an edit. Repeat with keyboard-only toolbar navigation where supported; verify that hovering UI never edits the world and no input sticks after focus loss. Record visible results and any unsupported affordance, not merely exit codes.

**Boundaries/non-goals:** `Renderer` remains content-free; client owns camera/player/scene/UI and submits draws to pass-owned resources. The game may depend on app/sim/physics as already established, but engine lower layers never depend upward. Camera snapshots obey existing row-major/row-vector/LH convention. No new sim subsystem, physics rewrite, world format change, automatic snapshot bump, multiplayer, or invented building types. UI state is ephemeral. Explicit errors for operational actions; tests use `PPR_TEST_ASSERT`. One new source file and its CMake registration are one atomic change.
