# Cleanup and Oni Lighting Port Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `subagent-driven-development`
> to implement this plan task-by-task. The owner selected this execution method;
> retain the plan-review and acceptance gates. Steps use checkboxes for tracking.

**Goal:** Restore a playable application, obtain cleanup acceptance, then deliver
the approved 1024×1024 Oni-derived lighting, PBR, Hable presentation, display
exercise and repeatable Nsight analysis in the ordinary game.

**Architecture:** Keep content and world lighting in pass-owned world resources;
keep the generic Renderer camera/content-free. Reuse the owned frame packet,
single render lane, explicitly shared graphics queue and completion fences.
Separate reconstruction from `PostProcessPass`, and settle scene, resolve/post
and presentation submissions independently.

**Tech Stack:** C++23/C++20 modules, CMake/Ninja, Slang/Slang-RHI, existing GPU
PB-MPM simulation, Python 3.10+, Nsight Systems/Graphics; Linux/Vulkan and
Windows/D3D12 qualification.

**Spec:** [Owner-approved design](../specs/2026-11-10-oni-port-design.md).
Read the entire spec; subsection titles below are normative references, not
permission to substitute an approximate implementation. The
[completed builder review](../specs/2026-11-10-oni-port-complete-builder-review.md)

## Global Constraints

- Rendered world: **1024 x 1024 cell map**; preserve other simulation API sizes.
- Cleanup first; explicit owner acceptance is required before Task 4 begins.
- Preserve simulation and particle evolution; preserve textured, normal-mapped
  PBR, roughness, metallic response, authored and supported thermal emission.
- “The owner alone accepts visual results.” Neither tests nor agents accept images.
- “Backward compatibility is out of scope.” No migration, legacy alias or selector.
- Owner naming correction (2026-11-11): use responsibility-based names throughout
  code. No `Oni`/`oni` reference in source filenames, symbols, namespaces, modules,
  shaders, tests, scripts, comments, runtime strings or profiler markers. Keep
  source provenance/attribution in documentation; do not copy reference names into
  implementation code. This applies to retained code as well as new work.
- Preserve unrelated work and the paused Task6b stash by object ID; preserve the
  temporary probe override and commented extent checks before deliberate replacement.
- Task 0 begins by committing **all current local modifications**, including
  unrelated work, as the owner-requested clean-slate checkpoint. Subsequent cleanup
  commits record deletions normally. Never commit copied/archive versions of removed
  code; any additional recovery archive and its manifest live outside Git.
- Sky hour defaults to **-1: black boundary sky**; integers 0..23 rotate the sky.
- Coarse intervals: **8-byte stride**. CH: **32-byte stride**, one **512 x 512**
  field, signed AC. Resolved cells: **4 bytes**. Source palette: **8 bytes**.
- hot64/cold24 solver rows remain unchanged; metadata stays **32 bytes**, alignment4.
- Jump table: **R8_UINT**, values **0, 1, 2, 4, 8, 16 and 32**. Unsupported storage
  is a blocker, not permission to widen it silently.
- L1–L5 update one probe per 2×2 group, all directions; reconstruct every fine
  probe every scene frame. No dirty/repair queues, ray budget or convergence stop.
- Thermal calibration: **6500 K → engine luminance one**; identical thermal LUT
  bytes and sampling for visible and source emission; opaque transport scope only.
- Hable is always on in the completed port; `R=ceil(W/P)`, `S=ceil(R/2)`, `B=2*S`.
  Pixelization P=1..8, default3; fixed-P nearest enlargement, right/bottom crop.
- One ordered graphics/compute queue; no per-frame CPU particle/image readback,
  steady-state wait-for-idle, new render graph or asynchronous lighting queue.
- Accepted A commits lighting; accepted B commits history/exposure; C reports
  presentation. Later failure cannot undo earlier accepted work.
- Ambiguous submit quarantines resources and stops admission; numeric-status
  readback is completion-fenced, bounded and required at shutdown too.
- No inherited 6 ms, register, ray, larger-map or no-regression performance gates.
  Measure the complete integration before proposing optimization targets.
- Apply YAGNI to every task: implement the smallest complete approved behavior,
  reuse existing facilities, and introduce no speculative capability or framework.
  The per-task review and Task19 enforce the concrete boundary below.
- Follow root/directory AGENTS/codemaps, module/source registrations, error macros,
  logical paragraphs/section headers, truthful noexcept and layout review.
- Linux success does not establish Windows success. Record every unavailable gate.

## Review Focus

1. A accepted, B rejected, then resize/world replacement: keep actual A progress
   and its readers while discarding only unsubmitted screen work (Task 14).
2. Temperature-only metadata replacement with unchanged particle count and a
   pending GPU reader: show the new temperature without corrupting old reads or
   copying stale CPU positions over the solver (Task 6).
3. A one-pixel valid region inside a padded/jittered backing, with extreme post
   settings: no invalid sample, padding contamination or lost histogram mass
   (Tasks 2 and 12).
4. A terminal ray starts outside the map, re-enters it and crosses a rotated sky
   seam: hit actual geometry or integrate the narrow sector, never attach sky
   early or integrate its complement (Tasks 8 and 9).
5. Close/minimize or a stale acknowledgment during a display trial/capture:
   terminate through production cleanup, retain partial evidence, never report a
   fabricated pass or act on another session's stop token (Tasks 17 and 18).

the completed plan. A later task's explicitly specified consumer is sufficient;
hypothetical reuse is not. Prefer a private helper or existing facility unless a

framework solely because two implementations look alike.

### Presentation values (Task 2)

In `engine.app:renderer.presentation`, namespace `pP`:

```cpp
struct PresentationGrid {
    int2 m_window, m_resolved, m_raster, m_backing;
    u32 m_pixel_scale;
};

Expected<PresentationGrid> makePresentationGrid(int2 framebuffer, u32 pixel_scale);

struct ResolvedHdrView {
    rhi::ComPtr<rhi::ITextureView> m_view;
    GridWorldIdentity m_world;
    int2 m_backing, m_valid;
};

struct PostProcessSettings {
    float m_exposure_ev{0.0f}, m_adaptation_tau{0.7f};
    float m_ev_min{-4.0f}, m_ev_max{4.0f};
    float m_bloom_intensity{0.125f}, m_bloom_threshold{1.0f};
    bool m_auto_exposure{true}, m_bloom_enabled{true};
};

std::error_code validatePostProcessSettings(const PostProcessSettings &settings);
```

`makePresentationGrid` accepts positive framebuffer dimensions and P1..8, uses
checked arithmetic, and rejects overflow. The caller handles zero framebuffer
as suspension before calling it. `ResolvedHdrView` is an immutable read binding
with a strong allocation reference; it does not alone prevent another GPU writer.
The producer and consuming submission retain/order its backing through final use.

`PostProcessPass` uses `initialize(IShaderService &, const std::filesystem::path &)
-> std::error_code`; `beginFrame(rhi::IDevice &, int2 resolved_extent,
GridWorldIdentity, FenceCompletionValue completed) -> std::error_code`;
`prepare(const PreRenderContext &, const ResolvedHdrView &,
const PostProcessSettings &, TimeSpan active_elapsed) -> std::error_code`;
`outputTexture() const -> rhi::ITexture &`; `render(const DrawContext &) ->
std::error_code`; `present(const DrawContext &, const PresentationGrid &) ->
std::error_code`. `prepare` encodes metering/exposure/bloom, `render` encodes AgX
into its own R-sized output attachment. `present` is the thin fixed-P output draw.
It has no scene callback, AA field or camera parameter. `beginFrame` selects and
allocates the output before the caller evaluates `outputTexture()` for
`renderToTexture`; it commits no exposure state. Pending output-slot exhaustion
returns capacity-busy without a steady-state wait. `prepare` validates the supplied
view against the selected output and retains it through B completion.

Each pass has `notifySubmitted(FenceCompletionValue) noexcept -> void` for its
own write stage, `discardUnsubmitted() noexcept -> void`, and
`collectCompleted(FenceCompletionValue) -> std::error_code`. Passes retain roots,
uploads and status tickets through completion. Post additionally has
`notifyPresented(FenceCompletionValue) noexcept -> void` to extend the selected
output's reader fence, including retained-picture draws. Ambiguous submission
calls neither normal discard nor normal commit; the existing terminal owner keeps
the entire attempted cohort quarantined. All these operations are owner-lane-only.
Each numeric-producing owner also exposes `finalize(const PreRenderContext &) ->
std::error_code`, which encodes its status-to-readback copies through Task13's
command-tail seam. WorldLightingPass finalizes after A's scene draws;
ReconstructionPass and PostProcessPass finalize after B's output draw. Tickets
are labeled/retained by that owner's corresponding accepted submission.

## Task 8: Full-domain visibility, R8 jump table and common segment tracer

**Files:** create `R/App.Renderer.WorldLightingPass.Transport.cpp`,
`ST/world_lighting_visibility.slang`, `ST/world_lighting_trace.slang`, `AT/App.WorldLighting.Trace.Tests.cpp`;
extend WorldLightingPass registration and the CPU reference helpers in `R/App.Renderer.WorldLighting.*`.

**Interfaces:** shader helper `Interval traceSegment(float2 start, float2 end)`;
uses resolved classification, R8 jump and cached source bindings. CPU test oracle
is a simple native-cell positive-length DDA, not copied jump traversal. Owner-private
`encodeAcceleration_(const PreRenderContext &) -> std::error_code` rebuilds all levels.
`ST/world_lighting_visibility.slang` exports compute entries
`buildVisibility(uint2 local : SV_GroupThreadID, uint2 group : SV_GroupID)` and
`buildJump(uint2 cell : SV_DispatchThreadID)`, both `[numthreads(16,16,1)]`.
Visibility uses one 21,504-record structured `uint2` buffer (stride 8, 172,032 bytes):
level record offsets `{0,16384,20480}`, row pitches `{128,64,32}`. Bind the resolved
cell buffer and material classification used by source preparation; receive-only
cells/gas are unoccupied and opaque black cells are occupied regardless of emission.

### Construction algorithm and synchronization

Use **two full-domain dispatches**, no per-cell neighborhood search or distance
transform. The first computes all visibility levels within each independent
32×32 native-cell tile; the second selects jumps using at most three uint2 loads.
The reference's tiled OR reduction already satisfies the aligned-block contract;
separate global reduction passes add dependencies, and approximate jump-flood
distances do not establish emptiness of the claimed aligned square.

1. `buildVisibility`: dispatch **32×32 groups**, 256 threads/group. A group owns
   a 32×32 tile at `group*32`. Each thread reads four resolved cells at
   `local + (0,0)/(16,0)/(0,16)/(16,16)` relative to that origin. These quadrant
   sweeps keep x-neighbor accesses adjacent and read each of the 1,048,576 cells
   exactly once; they are independent of camera visibility.
2. Reserve separate group-shared storage: **16 uint2-equivalent level-0 masks**
   (two arrays of 16 atomic uint words, 128 bytes) and **four uint2 level-1 masks**
   (32 bytes), **160 bytes total**. The first 4×4 threads clear level-0 words,
   then **all threads execute the group barrier**. An occupied local cell q
   atomically ORs bit `b=q.x%8 + 8*(q.y%8)` into word `b/32`, bit `b%32` of
   mask `q.x/8 + 4*(q.y/8)`. Empty cells do nothing. No global atomic is needed.
   All threads execute a second group barrier before any mask is read.
3. The first 4×4 threads store level 0 at record coordinate `group*4 + local`.
   The first 2×2 threads each read their disjoint 2×2 block of level-0 masks,
   OR every 2×2 group of bits into one bit, and assemble one 8×8 parent mask.
   Pack row-major: bit `x+8*y`, lower word rows 0..3, upper word rows 4..7.
   Implement the fixed reduction with word shifts/masks: horizontal OR by 1
   and mask `0x55555555`, vertical OR by 8, select even rows, compact each
   surviving four-bit row, then place the four 4×4 quadrants into the 8×8 parent.
   Store level 1 at `group*2 + local` and in the **separate** four-record shared
   array. Do not overwrite level-0 shared slots: another reducer may still be
   reading them, even though its neighbor has completed its own loads.
4. All 256 threads execute a third group barrier. Thread (0,0) applies the same
   reduction to the four shared level-1 masks and stores level 2 at `group`.
   Every global record has exactly one writer, including all-zero tiles; no
   global clear, inter-group synchronization, wave-size assumption or retained
   mask is required. Barriers are outside divergent branches; no early return
   bypasses them. Do not copy the prototype's in-place shared-array reuse.
5. Encoder orders resolved-cell writes before visibility reads, then applies a
   GPU write→read dependency for visibility before `buildJump`. Dispatch jump
   at **64×64 groups**, one thread per native cell. For level l, load the mask at
   `offset[l] + ((cell.y >> l)/8)*pitch[l] + (cell.x >> l)/8`; test bit
